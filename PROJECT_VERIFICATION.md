# Project Verification Matrix

**Author:** Edward Ocran

**Scope:** Projects 1–100

## How to read this matrix

`DATASET.md` is reserved for projects that genuinely depend on a dataset or recorded corpus. `INPUTS.md` documents source documents, webpages, fixtures, prompts, or deployment inputs that are not training datasets. Every project retains `ANALYSIS_REPORT.md` as a stable portfolio filename, but the report title identifies whether the content is an analysis, technical evaluation, deployment validation, safety evaluation, simulation evaluation, or reflection review.

The GitHub workflow performs dependency-light smoke validation across all 100 entry points. A smoke pass confirms interface and core behavior; it does not claim that every external service, microphone, hardware device, large model, or full dataset was rerun on GitHub.

## Validation commands

Run the repository-wide smoke suite:

```powershell
python validate_all.py
```

Run full project entry points for a selected range after installing each project's dependencies and retrieving its documented inputs:

```powershell
python validate_full.py --from-project 91 --to-project 100
```

Environment-dependent projects must also be checked in their target environment before making deployment, microphone, external-service, or hardware claims.
